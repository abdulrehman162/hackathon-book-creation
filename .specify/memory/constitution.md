# AI / Spec-Driven Book with Embedded RAG Chatbot Constitution

## Core Principles

### Spec-First Workflow
All development follows the Spec-Kit Plus methodology; Specifications must be complete before implementation begins; Every feature starts with a clear, agreed-upon specification

### Technical Accuracy
All technical information must come from official sources only; Third-party documentation, API references, and verified examples are required; No assumptions or unofficial sources allowed

### Developer-Focused Writing Style
Documentation and code must be clear and accessible to developers; Examples should be practical and runnable; Writing style must prioritize clarity and usability

### Reproducible Setup and Deployment
All setup and deployment procedures must be completely reproducible; Documentation must include step-by-step instructions that work for all users; Environment setup must be deterministic

### No Hallucinations
AI-generated content must be factual and grounded in source material; No fabricated information, code, or documentation allowed; All claims must be verifiable against official sources

### End-to-End Reproducibility
Complete workflows from setup to deployment must be reproducible; All dependencies and configurations must be documented and version-controlled; Full project lifecycle must be replicable by others

## Technology Stack Requirements

Book Framework: Docusaurus
Deployment: GitHub Pages
RAG Chatbot: OpenAI Agents / ChatKit, FastAPI, Neon Postgres, Qdrant Cloud
Source Control: GitHub-based

## Development Workflow

Implementation via Spec-Kit Plus methodology
Code quality: Runnable and well-documented
RAG grounding: Book content or user-selected text only
All specifications must be implemented as defined

## Governance

Constitution supersedes all other practices; Amendments require documentation and approval; All PRs/reviews must verify compliance with Spec-Kit Plus methodology; All code must be runnable and well-documented
